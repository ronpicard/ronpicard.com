In this notebook, we will walk through how to perform linear regression using gradient descent. The goal for this example is to predict what the profit for a new food truck might be given the population of the city. The input data to our model is the population of a city, and the output is the predicted profit. Since this is a 2-D linear regression model, the classic equation of a line is our model.

This is the first of two homework exercises from a deep learning course. It is written in plain NumPy, with no machine learning library, so every step of gradient descent is visible in the code.

The data and the model

The data file has two columns: the population of a city and the profit of a food truck there. Each row is one city. We want a function that takes a population and returns an expected profit. With a single input, the model is a line, written here with a bias term:

h(x) = θ₀ + θ₁ · x

To compute every prediction at once, we add a column of ones to the inputs so that the bias becomes just another parameter. Stacking the inputs into a matrix X (one row per city, a 1 followed by the population), all predictions are a single matrix product, Xθ.

Normalising the features

Before training, we standardise both columns by subtracting the mean and dividing by the standard deviation:

x ← (x − mean) / std

This matters for gradient descent. Raw populations and raw profits live on very different scales, so the cost surface is a long, narrow valley: steep in one direction, almost flat in the other. A single learning rate cannot suit both, so descent zigzags or crawls. After standardising, both axes have the same spread and the cost surface becomes a round bowl, where the downhill direction points almost straight at the minimum. The price is bookkeeping: any new population we want to predict for must be normalised with the same mean and standard deviation, and the prediction must be scaled back to profit units at the end.

Cost, gradient and update

We measure how wrong the line is with the squared error, averaged over the m cities (the extra 2 in the denominator cancels when we differentiate):

J(θ) = (1 / 2m) · (Xθ − y)ᵀ(Xθ − y)

Differentiating with respect to θ gives a gradient that has the same shape as θ, so both parameters are updated together:

∇J = (1 / m) · Xᵀ(Xθ − y)
θ ← θ − α · ∇J

Here α is the learning rate, the size of each step downhill.

Training

We start θ at (1, 1), chosen arbitrarily, with α = 0.1, and run 100 iterations of batch gradient descent, recording the cost at each step. The core loop is:

for i in range(interations):
    hx = np.dot(x, theta)
    hx_minus_y = hx - y
    j = np.dot(1/(2*m), np.dot(np.transpose(hx_minus_y), hx_minus_y))
    x_transpose_x = np.dot(np.transpose(x), x)
    dj_dtheta = np.dot(1/m, np.dot(x_transpose_x, theta) - np.dot(np.transpose(x), y))
    theta = theta - np.dot(alpha, dj_dtheta)

The whole run takes about 2 milliseconds.

Results

The cost starts at 0.662 at θ = (1, 1), falls to 0.157 by iteration 20, and then flattens at 0.149. That floor is the lowest cost any straight line can reach on this data, because the points are not perfectly aligned.

The final parameters in normalised units are θ₀ ≈ 0.00003 and θ₁ = 0.838. The intercept is essentially zero, as it must be: after standardising, the best line passes through the mean of the data. The slope of 0.838 says that a city one standard deviation above average in population is expected to have a food truck profit 0.838 standard deviations above average.

To get a prediction in dollars, we normalise the population, apply the line, and multiply by the profit standard deviation and add back the profit mean.

A note from 2026

The output cell saved in the original notebook came from a different run and shows θ₁ = −0.139, which disagrees with the 0.838 reported in the text. The figures above recompute the 100 iterations from the stated settings; they reproduce the notebook's own θ₀ and the 0.838 slope, so we treat 0.838 as the correct result. The elapsed time was also labelled milliseconds but is really seconds.

Takeaway

With standardised features, a handful of iterations is enough to fit a line by gradient descent. The same vectorised cost, gradient and update carry over unchanged to more features, which is the subject of the next post. The full notebook, with every cell and plot, is on GitHub.
