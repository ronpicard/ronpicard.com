In this notebook, we will walk through the design, training, and testing of a neural network with one neuron. This network performs logistic regression, an older name for binary classification.

The classification is performed on images of handwritten digits, specifically the last digit of my student ID, which happens to be 9. The goal of our network is to output 1 when the image shows a 9, and 0 in all other cases.

The data

We use the MNIST dataset, a long-standing benchmark in machine learning. Its training file holds 60,000 images, each 28 by 28 pixels, with a label from 0 to 9. Since we only care about nines, we relabel: every image labelled 9 becomes 1, and every other image becomes 0. Each image is flattened into a vector of 784 pixel values and scaled to the range 0 to 1 by dividing by 255. The images are taken in file order, with no shuffling.

We use three splits. A small validation run uses 500 training and 100 test images to check that the code works. The main run uses 50,000 training images and 10,000 test images. A data-size experiment trains on 10,000 images and tests on the same 10,000 test images.

One neuron

The model multiplies each of the 784 pixels by its own weight, adds them up with a bias b, and passes the total through the sigmoid function so the output is a probability between 0 and 1:

z = wᵀx + b
a = σ(z) = 1 / (1 + e⁻ᶻ)

We predict 1 (the image is a 9) when a ≥ 0.5, and 0 otherwise.

The loss

For a probability a and a true label y, we use the cross-entropy loss:

L(a, y) = −y · log(a) − (1 − y) · log(1 − a)

When the image is a 9 (y = 1) only the first term is active, and the loss grows without bound as a approaches 0. When it is any other digit, only the second term is active, and the loss grows as a approaches 1. Confident wrong answers are punished hardest.

To train the weights we need the gradient of the loss. Applying the chain rule, dL/da · da/dz simplifies neatly to a − y, so for one image the gradients are dz = a − y, dw = x · dz and db = dz. Over all images at once this is vectorised as:

dZ = A − Y
dW = (1 / m) · X dZᵀ
db = (1 / m) · Σ dZ
w ← w − α · dW, b ← b − α · db

Training is plain batch gradient descent, with no momentum and no minibatches.

Training

For the main run, all weights and the bias start at 0.1, the learning rate is α = 0.01, and we take 300 steps over all 50,000 training images. Each step does a forward pass, a backward pass and an update:

    Z = np.dot(np.transpose(W), X) + b
    A = 1/(1 + np.exp(-Z))
    term1 = np.multiply(-Y, np.log(A))
    term2 = np.multiply((1 - Y), np.log(1 - A))
    L = term1 - term2
    cost = np.multiply(1/m, np.sum(L))

    dZ = A - Y
    dW = np.multiply(1/m, np.dot(X, np.transpose(dZ)))
    db = np.multiply(1/m, np.sum(dZ))

    W = W - np.multiply(alpha, dW)
    b = b - np.multiply(alpha, db)

After every step we also measure accuracy on the 10,000 test images, which produces the accuracy curve.

Results

A quick validation run on 500 images checked the code before we moved on to the full set. With 50,000 training images, α = 0.01 and 300 steps, the network classifies 96.40% of the 10,000 test images correctly. The notebook also shows one example each of a true positive, a true negative, a false positive and a false negative. Reducing the training set to 10,000 images, with 100 steps, gives 92.72%, so more data helped.

The last experiment keeps 50,000 images but drops the learning rate to α = 0.00001. After 100 steps the cost is still 481.39 and accuracy is 9.61%. The steps are simply too small for the weights to move away from their starting values.

That baseline changes how the numbers should be read. About 9.61% of the test images are nines, so 9.61% is exactly what a network scores if it answers "9" every time, which is what the tiny-learning-rate run does, since its starting weights push every score positive. Always answering "not a 9" would score 90.39%. Judged against that, the 92.72% run is only slightly better than doing nothing, while the 96.40% run cuts the error rate from 9.61% to 3.60%, almost two-thirds fewer mistakes.

A note from 2026

In the notebook's code, the cost and gradients are divided by 784, the number of pixels, rather than by the number of images. This rescales the effective learning rate and is why the reported cost values, such as 7.37 for the main run, look large for a classifier that is 96% accurate. The accuracy figures are unaffected. The test set was also used to monitor accuracy during training, rather than a separate validation set.

Takeaway

A single neuron with a sigmoid is enough to pick out nines with a useful degree of skill, provided the learning rate is sensible and there is enough data. It also shows why a classification score always needs a baseline for comparison. The full notebook, with every cell and plot, is on GitHub.
